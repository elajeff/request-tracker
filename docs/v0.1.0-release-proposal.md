## Proposed release notes

Request Tracker v0.1.0 is a source-only local-lab release. It includes request editing/status/priority, staff directory and assignment rules, stable queue/history pagination and search/filtering, conservative Flyway migrations, and a TypeScript dashboard. Local infrastructure covers Compose, kind/Helm, monitoring, Argo CD/Rollouts, k3s practice through k3d, and an isolated PreviewEnvironment controller with expiry, ownership checks, restricted pod admission, and retention-aware cleanup.

Recorded verification includes 24 backend tests, frontend builds/API checks, 14 controller unit tests, the completed revised 24-check controller E2E runner, backup restorations, database recovery, and measured release promotion/automatic abort. Dashboard acceptance passed manually; no automated browser coverage is claimed. The capstone Git-published release demonstration counted 165 HTTP 500s in 6,360 normal-route requests. Its 39 restoration-window failures occurred during abort settling before the restore commit was first observed; all remain counted. Stable diagnostics were separate, and original healthy source configurations and data were restored.

This is not production readiness or a bit-for-bit reproducibility claim. It has no application authentication, production SLO, HA storage, or audited encryption-at-rest guarantee. The diagnostic-Service endpoint-gap limitation remains documented; no zero-downtime guarantee is made. Images are built/imported locally, example tags are not published registry artifacts, and trusted administrators/application images remain part of the security boundary.

Accepted deferrals: formal SLO definition; configuration-error/whole-cluster recovery exercises not demonstrated; broader certification labs and RKE2; video recording; published image/binary distribution and clean-machine bundle verification. Deferred work is not described as completed. Written commands/results exist; no screen recording was captured.

## Prerequisites and instructions

- For local source builds: Git, Java 21, Node.js 24/npm, PostgreSQL 17, and the included Maven wrapper. Alternatively use the Docker-based build paths.
- For the recorded Kubernetes labs: Linux containers through Docker Desktop/WSL2 on the tested Windows host, kubectl, Helm, and kind or the approved k3d v5.9.0 helper running actual k3s. The recorded clusters use Kubernetes/k3s 1.37; restricted policy is pinned to v1.37. Native-service and other-platform verification is not claimed.
- Build/import the required application/controller images and use explicit contexts, an isolated database/PVC, and fresh credentials. The controller uses its pinned Python image; verification scripts also require a local Python CLI. Follow capacity checks before running both clusters.

- [Executed demonstration](runbooks/capstone-demonstration.md), [delivery/recovery limitations](runbooks/delivery.md), [database recovery](runbooks/local-recovery.md), [security review](runbooks/security-capstone.md), [release checklist](release-checklist.md).
